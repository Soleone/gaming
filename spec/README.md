# Gaming specification

A curated video-game release calendar with personal hype ratings and played reviews. Browse one year at a time, optionally narrowed to a month. See [maintenance](../docs/maintenance.md) for storage and development details.

Behavior uses stable `area.behavior` slugs. Tests begin their titles with the corresponding slug. Update the rule and tests together when behavior changes.

| `agent.research`    | A visitor asks the local agent to research a game                      | A local pi-durable conversation uses the configured pi-web-access search provider (including keyless Exa), or OpenAI hosted search through Pi login when no search provider/key is configured. When Exa is selected alone, quota, empty-response, network, temporary, or unsupported failures fall back to OpenAI through Pi credentials; explicit lists/routes and provider allowlists still apply. Temporary failures on OpenAI or other routes get at most one retry, never for authentication or quota failures on the same provider. All attempts share the original timeout and cancellation; results identify the provider used, and errors identify the failure category without exposing raw responses. Source-linked results are verified against original pages; page reads include bounded navigation links and image candidates in page order with their alt text, taking full-size images from <noscript> over hidden blurred placeholders and the widest srcset or <picture> source over a small fallback src. Each message is limited to 30 tool calls shared by every game it asks about. Source text is untrusted. The model has no shell or collection-writing tools. |
| `agent.proposal`    | The agent proposes game facts                                          | The proposal is schema-valid, cites a page read by the agent, preserves release precision, and contains no personal ratings or reviews. It changes only title, release, source, and optionally the cover. The agent sees the collection titles and reuses an existing title for a game already collected. A message asking for several games yields one proposal per game, each saved on its own.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `agent.steps`       | The agent works on a reply                                             | Consecutive assistant messages read as one reply. Adjacent tool steps share one trace list, and text or a proposal between them starts a new one. Each step's title states its status and subject: present tense while running, past tense when done, "Failed to …" on error. Steps with output expand to show it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `agent.cover`       | A proposal offers cover candidates                                     | Candidates preview as 16:9 tiles loaded from their source without a referrer, next to the current cover when the target has one; a failed preview shows a placeholder. Clicking a tile opens a large in-app preview of the whole image, with previous/next across the options and Use this cover to select it; the selected tile carries a ring. Nothing downloads until the proposal is saved or opened in the form, and only the selected candidate of a completed proposal can be downloaded. Bounded JPEG/PNG/WebP still images at least 600px wide are re-encoded to content-named local WebP files; existing files are not overwritten. Selecting the current cover keeps the cover unchanged.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `agent.save`        | A visitor saves a proposal from the agent                              | One action downloads the selected cover and writes games.json. It updates the collection game whose title matches (ignoring case, accents, punctuation, and ™/®/©); otherwise the open draft when it is that game or still unsaved; otherwise it adds a new game. The button names the outcome (Update <title> or Add to collection) before saving. Hype and reviews are preserved, and an open draft with unsaved edits to another game stays untouched. Review in form instead applies the facts and cover to the open draft, or opens the matching or a new game in the editor; late downloads apply only to the draft that was open when chosen.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `agent.cleanup`     | A save writes games.json                                               | Afterwards, agent-downloaded covers referenced by no saved game and not held by the open draft are deleted. Other files in public/covers are never touched.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `agent.network`     | The local agent fetches a source or cover                              | Only public HTTPS destinations without credentials are accepted. Private and reserved DNS/IP destinations are refused; the public address is pinned and each redirect is revalidated. Downloads are time- and size-bounded.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `agent.safety`      | A browser accesses the local agent                                     | Only development middleware exposes the endpoint. Loopback and same-origin protections apply; conversations require a per-server token, and mutations also require matching Origin and JSON content type. Invalid or oversized requests never run tools.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `agent.sidebar`     | The local app is open                                                  | A persistent button opens a self-contained right agent dock with independent transcript scrolling. Minimizing preserves conversation and unsent prompt. Mobile uses a dismissible side sheet. The editor and agent remain independently usable on desktop.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `agent.models`      | A visitor selects model or effort                                      | Offer Pi's scoped/enabled models, not the provider catalog; unavailable entries remain visible but disabled; without a scope, offer only its saved default. Resolve thinking from scope suffix, per-model preference, then global default, clamped to supported levels. Choices persist locally per conversation, never change Pi settings, and cannot change during active work.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `agent.credentials` | The agent needs model access                                           | It reuses Pi's local credentials and configured models, including compatible custom models, without loading Pi's tools or extensions. Credential refresh is locked across processes and preserves unrelated providers. Search reuses pi-web-access configuration and server-side Pi credentials without registering its general tools. Credentials and credential commands are never exposed to or executed by the browser/model; command-based search credentials and malformed secret-bearing configuration are rejected safely.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `agent.persistence` | The editor or server reopens                                           | The app-wide conversation reconnects to local persisted history, and pending work resumes. Each message carries the current draft or explicitly no draft. Stop cancels work; New conversation resets history without changing the draft or model choice.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `editor.draft`      | A visitor closes or switches games with unsaved edits                  | Discarding requires confirmation; save failures leave the draft intact.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `nav.routes`        | A visitor moves around the app                                         | The URL names the view: `/`, `/2026`, `/2026/10` and `/unscheduled` for the calendar, `/edit` and `/edit/:id` for the editor (development only).
